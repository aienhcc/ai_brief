한 줄 요약

도구 경쟁은 사실상 무승부로 정리됐고, 대신 스킬이 수천 개로 불어나면서 “뭘 깔지”가 새 문제가 됐습니다. 동시에 “AI가 한 번에 너무 많이 만들어놔서 나중에 손 못 댄다”는 경고가 여러 곳에서 나왔습니다.

이번 주에 딱 하나만

“한 번에 다 만들어줘”를 끊으세요. 다음 작업부터는 만들기 전에 /grill-me로 기획을 굳히고, 한 번에 화면 하나 / 기능 하나씩만 시키세요. 이번 호의 3번 항목이 그 이유입니다.

알기만

모델 1등 싸움은 끝났습니다 — 소수점 차이

이게 뭐냐

코딩 실력을 재는 시험(Terminal-Bench 2.1)에서 GPT-5.6 Sol이 89.5%, Claude Opus 5가 89.1%를 기록했습니다. 0.4%p 차이는 사람이 체감할 수 있는 차이가 아닙니다. 두 도구 모두 이미 그 모델을 기본값으로 쓰고 있습니다(Codex는 7월 9일부터, Claude Code는 7월 24일부터).

나한테 쓸모

“어느 AI가 더 잘해요?”를 검색하는 데 쓰는 시간이 가장 낭비라는 뜻입니다. 같은 모델이라도 지시를 어떻게 주느냐에서 나는 차이가 저 0.4%p보다 훨씬 큽니다. 모델 갈아타지 말고, 쓰던 걸 계속 쓰세요.

지금 바로

스킬이 수천 개가 됐고, 설치 수 숫자는 믿을 게 못 됩니다

이게 뭐냐

스킬(AI에게 특정 작업 요령을 알려주는 폴더) 목록 사이트가 1,000개를 넘겼고, 대표 모음집들이 GitHub 별을 수십만 개씩 받고 있습니다. 최근 뜨는 것들은 영상·설계도·집중력 보조처럼 코딩이 아닌 쪽으로 번지고 있습니다.

왜 중요하냐

같은 스킬을 두고 어떤 사이트는 “80만 설치”, 어떤 사이트는 “764 설치”라고 씁니다. 집계 기준이 제각각이라 숫자 자체가 의미가 없습니다. 순위표를 보고 고르면 광고를 보고 고르는 것과 같습니다.

나한테 쓸모

고르는 기준을 숫자에서 “내가 지난달에 실제로 짜증났던 일”로 바꾸세요. 스킬은 많이 깔수록 좋아지는 게 아니라, 안 쓰는 게 깔려 있으면 AI가 엉뚱한 걸 꺼내 써서 오히려 나빠집니다. 다섯 개 넘기지 마세요.

고를 때 이렇게 물어보세요
"내가 최근에 반복해서 겪은 불편은 이거야: (예 - 만들고 나면
 내가 원한 게 아니어서 갈아엎는 일이 잦다)
 이걸 해결해주는 스킬이 실제로 있는지 찾아보고,
 없으면 나한테 맞는 스킬을 직접 하나 만들어줘."

스킬 설치는 폴더 하나 넣는 게 전부입니다:
  C:\Users\CKS\.claude\skills\  ← 여기에 스킬 폴더를 넣고
  Claude Code를 껐다 켜면 끝.
지금 바로

“겉보기 멀쩡한 거대한 결과물” 경고가 나왔습니다

이게 뭐냐

AI가 한 번에 아주 많은 코드를 쏟아내면, 당장은 잘 돌아가는 것처럼 보이지만 나중에 아무도(AI 포함) 손댈 수 없는 덩어리가 된다는 지적이 이번 주 여러 곳에서 나왔습니다.

왜 당신에게 특히 중요하냐

코드를 못 읽으면 “잘 돌아가는 것”과 “잘 만든 것”을 구분할 방법이 화면밖에 없습니다. 그래서 비개발자가 이 함정에 가장 잘 빠집니다. 3주쯤 뒤 “색깔만 바꿔줘” 같은 부탁에 AI가 엉뚱한 데를 건드리기 시작하면 이미 늦은 겁니다.

예방법 — 규칙 세 줄

완벽한 해법은 없지만, 아래 세 가지만 지켜도 대부분 막힙니다.

CLAUDE.md에 붙여넣으세요
## 작업 방식 규칙
1. 한 번에 화면 하나 또는 기능 하나만 만든다.
   여러 개를 동시에 만들지 않는다.
2. 파일 하나가 300줄을 넘어가면 먼저 알려주고,
   나눌지 말지 나에게 물어본다.
3. 작업을 시작하기 전에 "무엇을 바꿀 것인지" 3줄로
   먼저 말하고, 내가 동의하면 그때 만든다.
